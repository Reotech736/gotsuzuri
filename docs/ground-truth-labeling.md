# 静止画像の正解ラベル作成（ステップ4）

2026-10-25、本人の依頼により、モデルを試す前の評価データ作成を開始した。最初は本人が提供した上方撮影の写真1枚を分類する。モデル学習・AI導入・新しいAndroid機能は今回の対象外。

## 本人が行う作業

1. 分類画面で、①〜④と19×19交点が盤面に合っていることを確認する。必要なら四隅の丸をドラッグし、「位置合わせを確認した」を押す。最初の四隅はCodexによる概算なので、確認するまではラベル付けできない。
2. 盤面の交点をクリックし、右側の原寸周辺画像で空・黒・白・判別不能を選ぶ。番号は画像上の左上から1始まりの行・列。十字は盤面交点で、石上面の中心とは異なる場合がある。
3. すべて確認後、「盤全体を確認して分類を完了」を押す。自動保存の表示が「PCに保存済み」になったことを確認する。

ショートカットは0＝空、1＝黒、2＝白、3＝判別不能、矢印＝移動、Delete＝未分類。取り消しは同じ画面を開いている間の直近100操作まで。再読み込みしても保存したラベルは残るが、取り消し履歴は再読み込みで消える。

「まとめて操作・保存」には「未分類をすべて空にする」を用意した。これは本人が明示的に行う入力の省力化で、AIによる推定ではない。石の交点を黒・白へ修正し、盤全体を確認するまで確認完了にしない。四隅をやり直す場合は、確認表示に同意すると全ラベルを未分類に戻すため、必要に応じて先にJSONをダウンロードする。

写真から分からない場所を推測で埋めない。「判別不能」と「未分類」は別。判別不能はラベル付け済みとして記録するが、通常の空・黒・白の教師データには含めない。影のある写真で不明だった交点も、上方写真で見えることを本人が確認した場合には、その上方写真の正解を記録できる。ただし別画像へ自動でラベルを伝播しない。

## 保存と個人画像の扱い

最初のデータはGit管理外の `captures/labeling/reference-top-20261025/`。原写真のコピー `original.bin`、向きを補正して等倍の画素をPNGにした `source.png`、ラベル `annotations.json` を保存する。元の提供ファイルを変更せず、縮小・JPEG再圧縮をしない。原写真のSHA-256、画像寸法、四隅、データセットID、撮影グループを記録する。

初期値は361点すべて未分類、位置合わせ未確認、分類完了ではない。既存の認識結果・Codexの目視推定・暫定石数を正解として事前入力しない。分類完了は本人の明示操作で記録し、その後ラベルを変更すると完了状態を解除する。

変更はPC内のローカルサーバーへ自動保存し、直前の保存を `annotations.previous.json` に残す。保存失敗は画面に表示し、再保存またはJSONのダウンロードで退避できる。複数タブで同じデータを編集して更新番号が競合した場合は、古い画面からの上書きを拒否する。別の画像や別のデータセットのJSONは取り込めない。

サーバーは `127.0.0.1` のみで待ち受ける。外部サービスへの送信・クラウド保存・公開はしない。写真・ラベル・派生画像はすべて `captures/` に置き、公開リポジトリへ追加しない。Gitには作成ツールと説明・テストだけを追加する。

## 起動・再開

PythonとPillowが必要。今回のPCではCodex同梱のPython・Pillow 12.3.0を使用した。AndroidのJDKやGradle設定は変更しない。別環境では専用のPython環境へ `scripts/labeling/requirements.txt` を導入し、Pythonのパスを指定する。

リポジトリルートで実行する。

```powershell
.\scripts\labeling\start.ps1 -DataDirectory '.\captures\labeling\reference-top-20261025'
```

表示されたURLをPCのブラウザで開く。ポートは起動ごとに変わり得るため固定しない。同じデータのサーバーが動いていれば再利用する。Pythonを明示する場合は `-PythonExecutable 'Python実行ファイルのパス'` を追加する。起動は非表示の背景プロセスで、アプリや端末の操作は不要。

別画像を登録する場合は、次の例のように元画像・新しい保存先・ID・撮影グループ・概算四隅を指定する。既存フォルダへは上書きしない。画像ごとに位置合わせを本人が確認する。

```powershell
python .\scripts\labeling\server.py prepare --image '元画像のパス' --output '.\captures\labeling\新しいID' --id '新しいID' --group '同一配置のグループID' --corners '[[0.1,0.1],[0.9,0.1],[0.9,0.9],[0.1,0.9]]'
```

## 確認完了後の書き出し

```powershell
python .\scripts\labeling\server.py export --data '.\captures\labeling\reference-top-20261025' --output '.\captures\labeling\reference-top-20261025-crops'
```

本人による分類完了前は書き出せない。出力先は新しい `captures/` 内のフォルダのみ。原寸周辺画像361枚と `manifest.json` を出力する。周辺画像は隣接交点を含む範囲の軸に沿った切り出しで、射影補正・リサイズ・生成による補完をしない。元画像上の切り出し範囲、切り出し内の交点位置、行・列、ラベル、出典ハッシュ・ラベル更新番号・グループを保持する。境界では元画像外を補完せず切り詰める。モデルに渡す最終的な画像サイズや前処理は、モデル比較時に別途決める。

## 学習・評価の分離

現在は評価の入口を作る1枚の作業で、独立したテストセットが完成したわけではない。同一写真の切り出し・リサイズ・加工を学習用と評価用に分散させない。同じ石配置を別アングル・照明で撮った写真も同じ撮影グループとして管理し、最初の比較ではグループごと分ける。この1グループだけで汎化性能を主張しない。今後は別の配置・撮影条件を追加し、モデル・パラメータ調整に使わない評価グループを用意する。

`manifest.json` の分割は初期値 `unassigned`。まだ学習・推論処理はない。正解ラベルと現在の処理を照合できてから、小さなモデルの比較へ進む。

## 最初の本人確認済みデータと判定の比較（2026-10-25）

本人が分類完了ボタンを押した後、`annotations.json` の位置合わせ確認・分類完了・未分類0・元画像ハッシュを確認した。更新番号387で、正解は空309・黒26・白26、判別不能0。`captures/labeling/reference-top-20261025-crops/` に原寸切り出し361枚、`manifest.json` と確認時点の `annotations-reviewed.json` を保存した（すべてGit管理外）。この出力は更新番号387の固定された記録で、以後の画面編集は反映しない。ラベルを修正した場合は新しい出力先へ書き出し直す。

上方写真の向き補正済みPNGと本人確認済みの四隅を使い、現在のKotlinの色・周辺探索処理をPCで実行した。長辺2048への縮小はJava2Dの補間で、AndroidのImageDecoderと完全一致するものではない。参照した判定ソースのGit blobを比較JSONの `classifierRef` に記録した。

| 正解 | 正しく判定 | 不明 | 誤った確定判定 |
| --- | --- | --- | --- |
| 空309 | 296 | 13 | 0 |
| 黒26 | 25 | 1 | 0 |
| 白26 | 26 | 0 | 0 |
| 合計361 | 347 | 14 | 0 |

この1枚では空を石とする等の誤った確定判定はなかったが、黒石1点が不明となった。不明を一律に空へ変えると、その黒石を見逃す。上方写真1枚の開発用確認であり、別角度の画像・端末での性能やモデルの汎化性能とは区別する。学習・評価の分割は `unassigned` のまま、モデル学習も未実施。

比較ツールは `scripts/labeling/compare.py`。予測を `01 ...................` のような行番号＋19文字の形式で19行受け取り、`.`＝空、`B`＝黒、`W`＝白、`?`＝不明として正解と照合する。正解ラベルが判別不能の場合は通常の正解・誤り数から除外する。不明と誤った確定判定を別々に集計し、食い違いの行・列も記録する。

```powershell
python .\scripts\labeling\compare.py --manifest '.\captures\labeling\reference-top-20261025-crops\manifest.json' --predictions '.\captures\labeling\reference-top-20261025-crops\baseline-2048.txt' --output '.\captures\labeling\reference-top-20261025-crops\新しい比較結果.json' --method '処理条件の名前' --classifier-ref '判定ソースのGit参照'
```

結果は `baseline-2048-report.json` に保存済み。比較ツールは既存の結果を上書きせず、出力先も `captures/` 内に限定する。比較の未分類・不明・行列の重複・ラベル順序の検証4件を加え、Pythonのテストは合計10件成功した。
