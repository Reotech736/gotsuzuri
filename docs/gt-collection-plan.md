## 最初の作業量

初回は新しい3配置について、それぞれ「正解を確認しやすい上方」と「実際に使いたい固定位置」の2枚、計6枚を目安にする。一度に全写真の分類を依頼せず、1配置ずつ取り込む。下記の石数は撮影準備の目安であり、GTの答えや必須の枚数ではない。

| 配置 | 写すもの | 用途 |
| --- | --- | --- |
| A：少数・分散 | 黒白それぞれ6個程度。奥・中央・手前、左右へ分け、隣の交点には石を置かず離す | 開発用。基本の色判定と場所による位置ずれを見る |
| B：隣接した小集団 | 黒同士・白同士・黒白の隣接を複数箇所に作り、見える空の交点も残す | 開発用。隣石の拾い間違い、候補の分割・統合を見る |
| C：別の配置 | A・Bと異なる配置で奥・中央・手前、盤端にも石を分散する | 最終確認用として留保。方式・パラメータを決めるまで予測比較や調整に使わない |

これは性能を測るのに十分な枚数と保証するものではない。別配置でも改善が維持されるかを見る最小限の入口とする。Cを見て方式を修正した場合は、Cを未使用の最終確認用と呼ばず、新しい確認用グループが必要になる。

## 1配置あたりの撮影

1. 以前とは違う石配置を作る。四隅の最外周交点は石で隠さず、19路盤全体を写せるようにする。石数が目安と違っても、その実配置を正しく記録する。
2. まず盤面の石と交点が分かりやすい上方から1枚撮る。厳密な真上である必要はない。盤の向きが分かるよう、以後も同じ側を画像の上にする。
3. 石を動かさず、卓上スタンドの実際に使いたい固定位置から1枚撮る。奥側を無理に低角度にする必要はない。盤全体と四隅が見え、使い続けられる位置を優先する。
4. 最初のセットでは通常の室内照明を保ち、撮影途中に照明や石を変えない。カメラ角度以外の条件が完全に同じになるとは仮定しない。A〜Cの固定位置側は、できる範囲で同じ設置位置・画角を保つ。
5. 元のJPEGファイルをPCへ渡す。画面キャプチャ・再圧縮・画像の切り抜きで代用しない。途中で石を動かした場合や、画像の向きが変わった場合は、その事実を伝える。

現在のAPKで撮影できる範囲で進め、Android更新やADB接続を前提にしない。元写真を渡す方法は添付、またはこのPCで読み取れるローカルファイルのパスを使える。

## GT作成・保存と比較の順番

- 同じ配置の2枚は同一の撮影グループにまとめ、A・B・Cには別のグループIDを付ける。同じ画像の切り出し・加工や、同一配置の別角度を学習側と評価側へ分散させない。
- 写真受領後に元画像と向きを確認し、既存の `server.py prepare` でcaptures配下の新しいデータセットを作る。画像がない段階で概算四隅やGTを作らない。予測を正解の下書きにしない。
- まず各配置の上方写真で、本人が四隅・交点と361点の空黒白・判別不能を確認する。初期状態は未分類361点・未確認で開始する。
- 上方GTが完了した後、同じ配置の固定位置側に参考GTとして登録できる。ただし本人が配置・向き・位置合わせを確認して明示的に取り込み、写真全体を確認してから分類完了にする。実配置が分かることと、斜め画像で視認できることは区別する。
- 完了したGTを原寸切り出し・manifest・完了スナップショットとして新しい出力先へ固定する。現行PC判定の比較、候補の可視化は開発用A・Bから進める。CはGTの正確さを確認して保存するが、方式選択のための失敗例分析には使わない。
- 公開リポジトリへ追加するのは手順・コードと必要な集計だけ。元画像、GT、端末情報、派生画像・画面はcaptures配下で保持する。

ツールの操作方法は [GT作成の手順](ground-truth-labeling.md)、既存の比較画面は [可視化画面](assignment-visualization.md) を参照する。分類モデル用の学習データ形式・モデル・学習条件はまだ決めない。AWSのサービス選定・費用・クレジットの対象確認は学習方式が具体化した後に行い、現時点でクラウドへの画像送信や課金は開始しない。
