現在のAPKで撮影できる範囲で進め、Android更新やADB接続を前提にしない。元写真を渡す方法は添付、またはこのPCで読み取れるローカルファイルのパスを使える。

## GT作成・保存と比較の順番

- 同じ配置の2枚は同一の撮影グループにまとめ、A・B・Cには別のグループIDを付ける。同じ画像の切り出し・加工や、同一配置の別角度を学習側と評価側へ分散させない。
- 写真受領後に元画像と向きを確認し、既存の `server.py prepare` でcaptures配下の新しいデータセットを作る。画像がない段階で概算四隅やGTを作らない。予測を正解の下書きにしない。
- まず各配置の上方写真で、本人が四隅・交点と361点の空黒白・判別不能を確認する。初期状態は未分類361点・未確認で開始する。
- 上方GTが完了した後、同じ配置の固定位置側に参考GTとして登録できる。ただし本人が配置・向き・位置合わせを確認して明示的に取り込み、写真全体を確認してから分類完了にする。実配置が分かることと、斜め画像で視認できることは区別する。
- 完了したGTを原寸切り出し・manifest・完了スナップショットとして新しい出力先へ固定する。現行PC判定の比較、候補の可視化は開発用A・Bから進める。CはGTの正確さを確認して保存するが、方式選択のための失敗例分析には使わない。
- 公開リポジトリへ追加するのは手順・コードと必要な集計だけ。元画像、GT、端末情報、派生画像・画面はcaptures配下で保持する。

ツールの操作方法は [GT作成の手順](ground-truth-labeling.md)、既存の比較画面は [可視化画面](assignment-visualization.md) を参照する。分類モデル用の学習データ形式・モデル・学習条件はまだ決めない。AWSのサービス選定・費用・クレジットの対象確認は学習方式が具体化した後に行い、現時点でクラウドへの画像送信や課金は開始しない。
