## 起動と再開

Pythonと既存のPillowを使う。Gradle・JDK・Androidビルドは不要。

```powershell
python .\scripts\labeling\visualize_assignments.py build --results captures/labeling/candidate-assignment-20261027-v3 --centers captures/labeling/stone-centers-20261025/annotations-reviewed-r22.json --output captures/labeling/assignment-view-新しいID
python .\scripts\labeling\visualize_assignments.py serve --data captures/labeling/assignment-view-新しいID
```

1. 「写真」で上方・低角度・高い位置を選び、「比較条件」で補正なし／手動の一定位置補正を切り替える。既存の評価値と現行基準値を表示する。同じ写真の条件切り替えでは拡大位置を保つ。

3. 水色の円が色支持位置としての候補、水色の実線の先が割り当てた交点。橙色のひし形は未割当候補。候補を選ぶと、色支持率・集約点数・補正座標・最近傍と次点の交点・距離・未割当理由を表示する。色支持率を推定の正解確率と扱わない。
4. 「確認対象」で誤った確定判定、不明、未割当候補、現行から変化した交点、全候補を切り替える。一覧の対象を選ぶと周囲を拡大する。写真上の交点・候補もクリックで選べる。ドラッグで移動、ホイール／＋−で拡大縮小、「全体表示」で戻る。
5. 「集約前の支持点」を有効にすると、候補を構成した黒白のサンプルを表示する。候補を選択している場合はその候補の支持点だけを表示する。未割当候補の選択時は、最近傍・次点へ橙の破線を引く。これは成立した対応ではない。
6. 「補正後の仮想位置」は桃色の四角と破線で示す。石が実際にそこに見えるという意味ではない。補正座標が盤外なら仮想位置を外挿して描かず、詳細に盤外と表示する。「GTの石配置」は参照レイヤーで、推論の入力ではない。

交点の赤い四角は誤った確定判定、橙の輪は不明。判別不能GTは通常の誤りの印から除外する。候補がない交点にもGT・現行・PC試作の状態を表示するため、石を拾えていない例と対応先を誤った例を区別して調べられる。ただし候補と真の石の自動の同一性判定は追加していない。候補数を石数と扱わない。

## 画像と出典の扱い

表示用には元画像の縦横比を保った長辺2048以下のJPEG（quality95、色差サブサンプリングなし）を作る。再縮小・再圧縮した色や細部を色しきい値の検証に使わない。元PNGもバイト列を保って出力へコピーする。表示上の位置は正規化画像座標から投影し、元の交点や予測は変更しない。候補・支持点の画像位置と補正後の仮想位置を混同しない。

このPCでは大きな原寸PNGのブラウザ転送が途中で切れたため、JPEGプレビューをJSONに同梱して表示する。画像はPC内だけで処理し、サーバーはローカルの表示ファイルだけを配信する。JSON・テキストのHTTP転送にはgzipを使用する。外部サービスへの送信・ブラウザやネットワークの保護設定の変更は行っていない。

`view-data.json` は6条件の表示データとプレビュー、`provenance.json` は入力・実装のSHA-256。生成前に評価時の入力ハッシュ・固定GT・manifest・予測と混同行列・候補IDと一対一対応・中心出典を検証し、生成後に入力の非変更を確認する。HTTPサーバーはHostを検査し、表示ファイル以外・パス逸脱を拒否する。POSTでの保存はできない。個人画像、GT、表示データ、画面キャプチャはcaptures配下でGit管理外のまま保持する。
