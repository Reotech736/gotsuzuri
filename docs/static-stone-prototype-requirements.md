# 静止画像の石配置を試験判定する試作（ステップ4）

更新日: 2026-10-25

## 確定した範囲

本人の「次のステップへ」の依頼を受け、ステップ3の位置合わせに続く小さな試作へ進む。撮影直後の静止画像で四隅を手動指定し、361交点について空・黒・白・不明の候補を表示する。動画・棋譜生成へは進まない。利用場面・撮影条件・四隅指定は [既存の要件](static-board-prototype-requirements.md) を引き継ぐ。

四隅を調整した後に「石の配置を試験判定」を押す。黒白の丸は石候補、緑点は空、橙の輪は不明。候補数の合計は361。候補は確定した局面ではない。「交点だけ表示」で比較でき、四隅の変更・指定の取り消し・別の撮影では古い判定を消す。回転時には同じ画像・四隅から再判定する。

## 今回選んだ実装と仮説

Codexが初回の比較用として選んだ方式は、木地の色を基準に交点周囲の明るさ・色を調べる端末内の簡易判定。学習モデル・ネットワーク・新しい権限は導入しない。表示用の長辺最大2048ピクセルの画像を使い、元JPEGは変更しない。

罫線の中心を避け、盤面座標から射影した周辺画素を調べる。木地を推定できない写真は全交点を不明とし、画素が少ない場所や色が混在する場所も不明にする。暖色の木地が十分見える条件が前提で、盤の材質・照明・石の反射・影によって誤る。

**不明の表示は遮蔽検出の保証ではない。** 手や石で隠れた交点を復元する処理はなく、影を黒、石の一部を空と誤る可能性もある。横寄りの撮影では石の厚みによって盤面交点と石上面がずれる。現在の設置角度でどこまで使えるかは実写検証が必要な仮説。

## この試作の確認条件

- 自動テストで罫線のある空盤、黒白・隣接石、端・四隅、混色、木地を推定できない画像、低解像度を確認する。
- アプリで撮影→四隅指定→判定→交点だけ表示→再判定ができ、四隅変更時に古い結果を残さない。
- 実写で候補と実配置を比較し、誤検出・見逃し・不明の場所を把握する。正解ラベルなしに認識率を報告しない。
- 全MVPの認識精度の目標や採用方式の確定は、この比較結果を見て相談する。

既存JPEGを表示用と同程度に縮小し、同じ判定処理へ渡した結果。数字は候補で、実際の石数ではない。画像と評価用プログラムはGit管理外に保管し、公開しない。

## 対象外・保留

自動四隅検出、学習モデル、レンズ歪み・石の厚みの補正、石配置の手動修正・永続保存、保存画像の選択、動画追跡、合法手・捕獲・手番・パス、SGF、KataGoは今回の対象外。

定量精度・許容できる誤り率、撮影角度・高さの変更、より高度な認識方式は保留。ステップ4完了は初回の候補表示だけでは判定しない。

## 交点周辺の探索を追加（2026-10-25）

本人の指摘を受け、盤面の交点と石上面の見える位置を別に扱う方針で実装を更新した。四隅や361交点は盤面基準のまま保持する。各交点から縦横それぞれ±0.4交点間隔を0.2刻みで調べ、色の根拠が十分な石候補を交点に対応づける。上下の向きは固定しない。これは探索範囲内の色支持位置であり、輪郭から石上面の真の中心を求めた結果ではない。

交点自体で黒白の根拠が十分な場合はその結果を優先する。近接した候補の重複・黒白の競合・対応先の評価が近い場合は不明とし、隣石を無理に割り当てない。候補の対応づけは局所的な比較で、盤全体の最適割り当てやカメラ・石の高さの推定は行わない。探索範囲を超えるずれ、盤外の石上面、隠れ・反射は引き続き限界となる。木地の基準・色判定のしきい値は従来と同じで、照明差への補正は今回追加していない。

表示では黒白の丸を探索した位置に描き、対応する盤面交点へ水色の細線を引く。交点自体で判定した場合は線の長さがゼロになる。四隅を石に合わせて動かす必要はない。

人工画像では上下左右へずれた黒白、隣接する異色石、盤端、二交点の中間で対応が曖昧な石のテストを追加した。中間の石は両交点とも不明にし、二重に数えない。既存の空盤・混色・低解像度等を含め、座標変換14件＋石判定12件＝26件が成功した。

### 保存済み画像での変更前後の比較

同じ元JPEG・同じ推定四隅・同じPC側縮小処理を使い比較した。四隅は過去の端末画面から推定した座標で、端末上の数値と完全一致せず、縮小もAndroidのImageDecoderとは異なる。以下を端末の認識率として扱わない。

| 画像 | 変更前（黒／白／空／不明） | 変更後（黒／白／空／不明） |
| --- | --- | --- |
| 空盤 | 0／0／346／15 | 0／0／346／15 |
| 横寄りの石配置 | 26／25／296／14 | 26／25／296／14 |
| 高い位置からの石配置 | 19／26／289／27 | 20／26／289／26 |

高い位置からの画像では、比較写真で黒石がある列17・行6（画像左上から1始まり）が不明から黒へ変わった。改善はこの1か所で、影・反射や他の不明は解消していない。探索を広げる初期案では隣石の影響で既存候補が不明になる退行があったため、交点自体の十分な根拠を優先する方式に修正した。

保存画像の孤立した石6点で、目視で選んだ上面位置と推定交点を概算比較した。1368×1824の表示相当で約1〜6ピクセル、盤面間隔換算では概ね0〜0.12程度の差だった。目視位置と推定四隅の誤差を含み、石の物理的な高さによる差だけを測定した値ではない。今回調べた点からは、上面の位置ずれだけが誤判定の主因とは断定できない。測定用コード・選んだ座標・結果・元画像はGit管理外の `.tools/tmp/stone-offset-evaluation/` と `captures/` に保存する。

最終APKのPOCO確認では、更新後の新写真に本人が四隅を合わせ、黒26・白27・空296・不明12を表示した。表示を消して再判定しても同件数で、4点と361交点の維持、新凡例も確認した。新写真なので上の固定画像比較とは区別する。白27は比較写真の暫定計数26を超えており、誤検出が残る可能性がある。候補の増加を成功とはせず、交点別の照合と本人の最終目視を次の確認に残す。
