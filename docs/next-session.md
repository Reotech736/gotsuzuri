## 次の開発タスク: 撮影の追加確認（ステップ2）

以下は未実施の確認項目。チェック済みにするのは実際の結果を記録してからとする。

- [ ] 現在の端末・ポートでWi-Fi接続し、APKを更新できることを確認する。既存アプリのインストール済み確認だけで、更新成功とみなさない。
- [ ] カメラ権限を拒否してもクラッシュせず、案内が表示されることを確認する。
- [ ] 端末のアプリ設定からカメラを許可し、復帰後にプレビューと撮影が使えることを確認する。
- [ ] 縦・横へ回転した後に撮影し、保存したJPEGを開いて画像の向きを確認する。
- [ ] ホーム画面へ移動してアプリに戻り、プレビューと撮影が再開できることを確認する。
- [ ] 連続して複数枚撮影し、それぞれ別ファイルとして保存・表示できることを確認する。
- [ ] 見つかった不具合を範囲内で修正し、変更した場合は `scripts/build.ps1` と関連する実機確認を実施する。
- [ ] 結果・不具合・未確認事項をREADMEの検証記録へ反映する。

権限ダイアログやインストール確認は本人が操作する。端末が接続できなければ未確認と記録し、ステップ2を完了扱いにしない。画像・動画・ペアリングコードは公開しない。

## 要件相談で詰めたいこと（まだ未決定）

`grilling` スキルを使う場合は一問ずつ、推奨案とその理由を示し、ユーザーの回答を待つ。ここに並べた論点を一度に質問しない。

- 最初に使う場面と利用者: 自分の通常対局、指導碁、碁会所などのうち、何を最初の検証対象にするか。
- 実際に置けるカメラの位置・高さ・固定方法。斜め撮影で隠れる交点をどこまで許容できるかは、回答だけで決めず実写で検証する。
- 対局前・対局中・対局後に許容できる操作。毎手タップをなくす目的と、初期設定や不明区間の修正に許容する負担を整理する。
- 途中開始、手番、パス、不明区間をどのように人へ確認するか。初期段階で扱う範囲を決める。
- 何ができれば次の試作を成功とするか。認識率など未測定の数値を根拠なく確約しない。
- 確認用映像が必要になる段階で、保存の有無・保存先・容量・保存期間を決める。今のJPEG保存と混同しない。

相談の成果は、合意した利用シナリオ・対象範囲・成功条件・保留事項を短い要件文書として残すこと。推奨案を回答済みの決定として記録しない。

## 次の試作: 四隅指定と交点表示（ステップ3）

実装開始前に、画像の入口（撮影直後／保存画像の選択）、四隅の指定順と向き、指定のやり直し、位置合わせの確認方法を合意する。

到達点の候補は「静止画像の最外周交点4隅を指定し、19×19交点を重ねて、人が位置合わせを確認・修正できる」。画像座標と論理碁盤座標を分離し、座標変換の境界条件や不正な四隅指定を自動テストで検証する。石の分類やSGF出力はこの試作の対象外とする。

文書の役割は、AGENTS.mdが作業ルール、READMEが全体の現在地・セットアップ・検証記録、要件文書が合意した仕様、Issuesが個別タスクの進行状況。Issue運用開始後は、この候補一覧を実際のIssueへのリンクに置き換え、複数箇所に同じチェックリストを保守し続けない。
